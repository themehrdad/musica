# iOS 27 compatibility check — October 28, 2026

Mehrdad asked whether Note School needs changes for iOS 27, because his other app (Digchi) crashed on testers' phones after they upgraded. This check made no code changes.

| Check | Result |
|---|---|
| Build with Xcode 27.1 / iOS 27.1 SDK | ✅ Version 1.2 (6) was already archived with it and approved by App Review on Oct 18 |
| 76 unit tests, iPhone 17 Pro Max, iOS 27.0 (24A434) | ✅ all pass |
| Every demo screen (profiles, practice, hints, goal, grand staff, progress, paywall), iPhone 17 Pro Max, iOS 27.0 | ✅ no crashes; layouts match iOS 26 |
| Same screens, **iPhone Duo**, iOS 27.1 (24A94425; this runtime supports only the Duo) | ✅ no crashes; wider window with the status bar on the right; nothing overlaps |
| SoundAnalysis `.version1` classifier labels | ✅ 303 labels, and `piano`, `electric_piano` and `keyboard_musical` are all present on 27.0, 27.1 and 26.5 |
| AudioKit engine start (mic → taps) in the simulator test host | ⚠️ fails with AVFAudio `-10875` (AUGraphParser InitializeActiveNodesInOutputChain), but **identically on iOS 26.5**, where the app works on real phones. This is a simulator limitation, not an iOS 27 regression |

- The paywall shows "Loading Subscription" in simctl demo launches because no StoreKit configuration is attached outside the Xcode scheme. The same happens on iOS 26.
- Digchi's recorded Xcode 27 fix (`02f7443`) was a CocoaPods deployment-target build failure in a React Native stack. Its runtime crash isn't recorded, and it doesn't share Note School's native stack (SwiftUI, SwiftData, AudioKit, StoreKit 2).

**Conclusion:** no changes are needed based on this testing. The only untested path is **real microphone and piano detection on a physical iOS 27 device**. Check it as soon as any tester's iPhone, or Mehrdad's, is on iOS 27: open Practice and play a few notes.
